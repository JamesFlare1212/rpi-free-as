## Course Text(s)

### Text Details:

Course will be taught from instructor provided notes. Additional useful resources as follows:

This is an incomplete set of some useful books, websites, etc.

- Stroustrup, *A tour of c++*, 2nd edition. Boston, MA: Addison-Wesley, 2018.
  - Excellent introduction to the C++ language by the creator of C++. Doesn’t contain too much detail, but does cover all the basics.
- Reddy, *API design for C++*. Burlington, MA: Morgan Kaufmann, 2011.
  - Some useful information about how to construct APIs. Does contain C++ specific information.
- Vandevoorde, N. M. Josuttis, and D. Gregor, *C++ templates: the complete guide*, Second edition. Boston: Addison-Wesley, 2018.
  - One of my favorite C++ books of all time. If you take the time to understand this book, you will understand the core of the language quite well.
- M. Josuttis, *C++17 - The Complete Guide - First Edition*.
  - Goes into good detail about C++17 changes/features.
- Meyers, *Effective modern C++: 42 specific ways to improve your use of C++11 and C++14*, First edition. Beijing ; Sebastopol, CA: O’Reilly Media, 2014.
  - Although this is “old”, it still contains an excellent set of tips for writing better C++ code. The author’s explanations are very clear. More beginner friendly that some of the other selected references.
- Scott, *Professional CMake: A Practical Guide*.
  - The best CMake documentation I have found to date. It’s hard to find accurate and up-to-date CMake information on the web that gives examples. (CMake documentation focuses on providing a reference only). This book is not expensive, and the author updates it frequently. If you purchase once, you get free updates every time he releases a new version.
- https://www.youtube.com/playlist?list=PLHTh1InhhwT4TJaHBVWzvBOYhp27UO7mI
  - Cppcon videos, especially “back to basics” track have a ton of good information.
- https://www.youtube.com/playlist?list=PLs3KjaCtOwSZ2tbuV1hx8Xz-rFZTan2J1
  - C++ weekly videos from Jason Turner are short videos discussing C++ content. They are easily digestible and it can be useful to see how he thinks about understanding various features.
- https://en.cppreference.com/w/
  - Goto reference material for C++ content.
- https://godbolt.org/
  - “Compiler explorer” lets you test out your code with various C++ compilers in real time. Very useful for figuring out errors or other well contained examples particularly with templates as compile-run loop is very short.
- https://cppinsights.io/
  - This shows you the “compiler view” of your code. It helps understand things like template instantiations, lambdas, etc.
- https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines
  - A useful set of guidelines for writing safer and cleaner code.
- CSCI-4320, Parallel Computing Course taught by Prof. Carothers in spring semester.
  - A must-take course for anyone doing computational research that relies on parallelism.
- C++ standard
  - Impenetrable, but it is the ultimate source of truth for any C++ knowledge. It is an ISO standard that costs money. But, the draft standard is free and should be the same besides formatting.
  - Most recent draft standard can be found here: https://eel.is/c++draft/ with older version here: https://github.com/timsong-cpp/cppwp

## Course Goals

### Goals:

This course introduces concepts and best practices for designing scientific and engineering software applications that are maintainable and can run at scale on massively parallel and heterogeneous computing platforms. Software methods and practices in this course will be applied to science and engineering software such as finite elements and multiscale/multiphysics simulations. Students will be expected to have some programming experience as well as familiarity with distributed or shared memory parallelism.

## Grading Criteria

### Criteria Details:

# Grading Policy:

- \- 10% class participation (in class exercises, quizzes, attendance)
- \- 50% homework assignments (software implementation, tooling, and code review)
  - o 30% for implementation, documentation, use of tooling, and testing
  - o 20% for code review (both performing code review and responding/updating code)
- \- 40% term project (software, writeup, presentation)

Course grades will be computed based on the percentages defined above. Grade modifiers that will be used in this course:

- A = 90 – 100
- B = 80 – 89.99
- C = 70 – 79.99
- D = 60 – 69.99
- F = <60 (Fail)

This grading policy is subject to change.

### Other Course Policies:

# Homework:

Homework should be completed in a timely manner. Since the course content builds on itself and you will be doing code reviews on each other’s code, late submissions will typically not be accepted. In limited circumstances, you may be able to obtain an extension. However, this requires permission from Prof. Merson and your code review partner.

# Term Project:

A significant portion of your grade will be based on the completion of a term project. You may work together on a larger project. However, your grade will be based on your individual contributions and you must have easily identifiable components of the work. You will submit individual reports and final projects.

A one-page project proposal must be submitted before or on 1/27. This should indicate the type of project and summary of the expected project activities. A 1-2 page project update will be due on 3/10. This should include a concise description of the activities carried out to date and those that remain to be carried out.

For your term project, I want you to contribute to or develop a piece of research software. This should be coordinated with your advisor if you are a PhD student. If you are not a PhD student, or do not have software components of research, please discuss with me. I can help to define a project based on work that my group is doing, or we can find an alternative open source piece of research software to contribute to such as MFEM or DEAL.II.

You must demonstrate and utilize the methods we have discussed during the semester such as unit testing, proper use of build systems, CI/CD, and effective use of C++. Other languages may be acceptable, but please confirm with me before doing this.

# Collaboration and Academic Integrity:

Student-teacher relationships are built on trust. For example, students must trust that teachers have made appropriate decisions about the structure and content of the courses they teach, and teachers must trust that the assignments that the students turn in are their own. Acts which violate this trust, undermine the educational process. Students are expected to conduct themselves in a professional manner at all times.

The instructor administers an academic (grade) penalty, and students may also enter the institute judicial process and be subject to such additional sanctions as: warning, probation, suspension, expulsion, and alternative actions as defined in the current *Handbook of Student Rights and Responsibilities.* The following specific collaboration rules apply to this class:
