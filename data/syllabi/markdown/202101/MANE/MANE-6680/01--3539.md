### Prerequisites or Other Requirements:

1. A finite element analysis course, or sufficient technical background in finite element methods. The preferred course would be MANE 6660 since I will assume that students know the material from that course (the first three chapters of T.J.R. Hughes, *The Finite Element Method: Linear Static and Dynamic Finite Element Analysis*)
2. A good working knowledge of C/C++ along with the associated code building (cmake) and debugging methods.
3. You must know how to program to take this course. The classes will cover concepts, methods and algorithms. It will not cover any programming details (documentation will be provided – but you must be able to work from that).

## Course Description

### Additional Course Description :

Course goals:

1. Cover the components of a finite element analysis program taking a geometry-based perspective. Parallel implementation of finite element methods will be covered.
2. Understand and implement a finite element analysis capability.
3. To carry out a specific project addressing an aspect of finite element programming.

Grading:

10% Assignment 1 - Mesh database

5% Assignment 2 - Parallel mesh database

5% Assignment 3 - Reordering procedure

30% Assignment 4 – Finite element analysis code development

50% Term project (software and write-up)

The course project selected will involve programming some aspect of the finite element method. The project selected must including programming. Since this project represents a major portion of the course, it is important that you begin it as soon as possible. The project you select should have a relationship to your research. Please note that the level of effort involved in this course is such that you only want to take it if the project is of specific value to your research.

## Course Content

### Content Details:

1\) Course overview and FEA review

1. a) Course overview
2. b) Brief review of FEA - Element shape functions, element stiffness integrals, numerical integration, recovery of secondary variables
3. c) Software for FEA

2\) The mesh as a topological hierarchy

1. a) Geometry and attributes
2. b) Mesh entities, mesh topology, and Mesh classification
3. c) Tutorial: Interface operators for interacting with the mesh using PUMI
4. d) Ordering of mesh entities

5\) Finite element analysis program

1. a) Introduction to MFEM C++ library for parallel, high-order finite element methods (https://mfem.org/) This introduction will not be covered in class. Watch the first 48 minutes of the video you will find at. https://www.youtube.com/watch?v=Zh6pFjkmr0g&list=PLGj2a3KTwhRbS2ghSgGvUjnVvEfv4US4R&index=7&t=0s (The rest of the video is material we will be covering in class in more detail than covered in the video.)
2. b) Tutorial: MFEM
3. c) Simplified finite element code
4. d) Object oriented finite element code
5. e) Implementation of p-version elements
6. f) Solving time dependent and non-linear problems
7. g) Iterative solution methods

3\) Parallel computing

1. a) Parallel computers and basic parallel constructs
2. b) Data parallel and message passing
3. c) Dynamic load balancing and task placement
4. c) Parallel FE analysis
5. d) Parallel mesh operations
6. d) An introduction the Omega_h parallel mesh infrastructures for GPU execution

8\) Adaptive finite element techniques

1. a) A posteriori error estimation
2. b) Mesh enrichment schemes
3. c) Automated adaptive workflows

### Course (Student) Learning Outcomes Assessment Measures:

For assignments 1-4 the students are to provide:

1. A description of the algorithm (e.g., which set of adjacencies are used to get the requested adjacency or how the mesh was generated and adjacencies constructed, etc.)
2. A copy of the code that is fully commented.
3. The other specific items requested in the statement of the specific operation or task.

The term project report is to include:

1\) Title, Name and Abstract

2\) Introduction.

3\) Discuss the methods investigated, approaches evaluated and selected. Present the theory behind methods used and include appropriate citations to the literature. (Could be more that one section.)

4\) Code design and algorithms/software used not covered in earlier sections.

5\) Pseudo code for the software developed.

6\) Code verification process and verification test results

7\) Results for problems of interest.

8\) Concluding remarks.

9\) References.

10\) Appendix containing listing of the code written for project.
