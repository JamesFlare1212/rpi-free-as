## Course Description

### Additional Course Description :

Software system design methodology emphasizing use of object oriented modeling of application domains and of software systems and emphasizing the roles of written and oral communication in software engineering. Project management and software testing. Individual and team projects include specification, software architecture, user interfaces, and documentation of the phases of a project. This is a communication-intensive course.

## Course Goals

### Goals:

The goal of this course is for students to learn through doing the many tasks and documentation associated with developing a full software application with a team. Along the way students get experience in regular team meetings, creating a working schedule using and iterative, agile software development methodology and related practices. The goal of the course is to emulate a professional software development environment.

## Course Content

### Content Details:

In this course we will discuss the following topics

- Software Development Processes (Waterfall, Scrum, XP, and other Agile approaches to software development)
- Object Oriented Design Theory
- Agile Development
- User Stories
- Use Cases
- Design Patterns
- UML
- Software Testing
- Development Best Practices
- Project Management
- Team communication

## Learning Outcomes

### Course (Student) Learning Outcomes (CLOs):

- Be able to envision, design, develop, and deliver a full software product with a team.
- Be able to communicate and collaborate effectively in a team development environment.
- Be able to describe and use design patterns in the design and development of your software.
- Be able to design and iteratively develop software using a story-driven approach.
- Gain valuable experience working cooperatively in a group with a common goal using a proven Agile software development methodology.
- Be able to coherently describe the differences between various software development processes in use today.
- Improve your confidence and ability to deliver a sophisticated technical presentation.
- Be able to read and draw simple UML diagrams.

Assessments:

- Sprint 1 Deliverables: Vision Statement, User Scenarios, Project Schedule
- Sprint 4 Deliverables: Product Interface Mockup, User Stories, Supplemental Specification, Deployment Diagram, Use Cases, Work Breakdown Structure, Updated Project Schedule
- Interim Release Deliverables: Initial release of software, Design Approach, Sequence Diagrams, CRC Cards, Static Class Diagram, Mock Interface Testing Plan
- Beta Release Deliverables: A feature-complete release of software, Code Review Summaries, Testing Documents (test plan, test case specification, test results template)
- Final Release Deliverables: Final Software Release, Final Test Results
- Peer Reviews
- Best Practices
- Recorded Technical Presentation
- Take Home Exam

## Policies

Students should be responsible for attendance with their groups. Students are responsible for everything mentioned in class.

### Other Course Policies:

Students must pass their exam to pass the class. If the exam is not received, students will automatically receive an incomplete. Penalties are imposed for late submissions. However, submissions will always be accepted.  
Students can receive extra credit for attending two document review sessions for their exam as well as doing an in-class presentation on their technical topic or some other pertinent subject. This must be pre-arranged with the instructor.

### Academic Policies:

- ### Academic Integrity

  Student-teacher relationships are built on trust. For example, students must trust that teachers have made appropriate decisions about the structure and content of the courses they teach, and teachers must trust that the assignments that students turn in are their own. Acts that violate this trust undermine the educational process. The Rensselaer Handbook of Student Rights and Responsibilities and The Graduate Student Supplement define various forms of Academic Dishonesty and you should make yourself familiar with these. In this class, all assignments that are turned in for a grade must represent the student’s own work. In cases where help was received, or teamwork was allowed, a notation on the assignment should indicate your collaboration.

  Violations of academic integrity may also be reported to the appropriate Dean (Dean of Students for undergraduate students or the Dean of Graduate Education for graduate students, respectively).

  If you have any question concerning this policy before submitting an assignment, please ask for clarification. In addition, you can visit the following site for more information on our Academic Integrity Policy: [Students Rights, Responsibilities, and Judicial Affairs](https://info.rpi.edu/dean-students/student-rights-responsibilities-and-judicial-affairs).
