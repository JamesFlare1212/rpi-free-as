## Course Description

### Additional Course Description :

Regardless of whether you consider yourself a writer, an artist, or a programmer, some amount of programming knowledge is essential when making games so that you can better understand how the various game components all come together to create the final whole. If you have a baseline comprehension of what goes into programming a game, it enables you to discuss technology with the rest of your team.  
This class serves as a primer in game programming using the C# language and the Unity game engine. It is intended for students of any programming skill level, from experts to complete beginners. What matters most in this class is the extent to which you grow as an individual, not how you compare to your fellow students at the end of the semester. Everyone has the ability to learn how to program as long as they are willing to put in the time and perseverance needed to practice and learn.

## Course Goals

### Goals:

- **Understand basic programming principles** and apply them effectively in game projects while engaging in meaningful discussions with other people.

- Be able to **write, debug, analyze, and document** code in C#. Ensure that both the writer and their collaborators can comprehend the code.

- **Identify how to use tools in Unity**. Be able to implement functionalities including script, sound, sprite, UI, physics, animation, camera, and lighting.

- Gain the experience of **creating playable digital games** from scratch in Unity.

- **Practice workflows in version control**. Develop the proficiency to create, save, resolve conflicts, and deploy using version control.

## Grading Criteria

### Criteria Details:

Text-based Adventure  
Due: 01/26  
Students will create a playable text-based game using C#. It is a warm-up exercise for learning the basics of programming.  
2D Adventure  
Due: 02/12  
Students will create a 2D adventure game using the Unity editor. The game should contain a controllable character, interactive objects, sound effects, and UI elements. The goal is to be familiar with Unity and C#.  
Physics Game  
Due: 03/09  
Students will create a 2D Physics Game using Unity. The game will be graded based on its concept, design, physics integration, and gameplay experience. The goal is to enhance the proficiency in using Unity along with the ability to write code that is readable and documented for collaboration purposes.  
Final Project - Platformer  
Prototype due is 04/02. Final due is 04/27.  
Students will create a 2D Platformer. The game should be well-polished with code, UI, animation, and sound. Game mechanics, level design, and narrative should be fully implemented. Due to the nature of a programming-oriented course, visual aesthetics are not rigorously enforced. However, it is essential to ensure that visual aspects do not compromise the overall quality of gameplay.  
Self Evaluations  
In each game due date, students will submit a self evaluation of their work. The evaluation should reflect on the student’s goals for the project, what they actually created, and how well they think they achieved their goals. The evaluation will be used as part of the grading for the associated assignment.

### Additional Academic Integrity Course Policy and Penalty Information:

Plagiarism  
Plagiarism is defined as representing the work or words of another as one's own through the omission of acknowledgement or reference. Examples include using sentences verbatim from a published source in a term paper without appropriate referencing, or presenting as one's own the detailed argument of a published source, or presenting as one's own electronically or digitally enhanced graphic representations from any form of media.  
Copying code either by cutting and posting, or copying it letter by letter is considered plagiarism (at a minimum). Code should be implemented in such a way to show that concepts have “taken up residence in your head”. That is, you should include comments, naming and programming style indicating and demonstrating your understanding and practice of the methods used.  
Appropriate Programming Practice  
Programming is rarely a solitary endeavor, but for the sake of academic integrity in this course, it is essential that you do your own work. There is a reasonable line between asking people for help and outright plagiarism. While you may ask your classmates for help or advice and show them problematic code, you may NOT view their working code in response. The reverse is true if you are asked for help; while you may offer advice and look at broken code, you may NOT share your code in response. Don’t try to guilt-trip people and don’t allow yourself to be guilt-tripped: friends don’t manipulate each other.  
Appropriate Tutorial Use  
We encourage beginners to use online tutorials as a learning resource. However, tutorial demos should not be used as your final submission. If you have used a tutorial as part of your learning process, please cite the source in your self evaluations. This shows academic integrity and helps demonstrate your journey from learning to creation.
